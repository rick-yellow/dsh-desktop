# Postmortems

This reference defines the only documentation tier that owns incident chronology. Create a postmortem for a user-visible failure, security event, release regression, data loss risk, or repeated operational outage that yields durable corrective work.

Name records `YYYY-MM-DD-short-slug.md` and include:

1. Impact and affected versions or environments.
2. Detection and time-ordered evidence.
3. Technical and process causes.
4. Resolution and recovery.
5. Corrective actions with owners or tracking links.
6. Verification that detects or prevents recurrence.

Separate evidence from inference and avoid blame. Link current product behavior back to its owning reference or decision record instead of turning the postmortem into a permanent usage guide.
